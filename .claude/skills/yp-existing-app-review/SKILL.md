# Existing-app review

Stay within this repository and current authorization. Do not commit, push, publish, change secrets/permissions, add integrations or overwrite unrelated work.

Read project instructions and inspect current implementation before importing recommendations from this pack. A newer checkout and explicit user decisions override the pack's historical observations. Inventory screens, data flows, design tokens, motion and current tests; do not assume a missing search result means a feature is absent.

Build a finite findings list with affected journey, evidence, severity and expected benefit. Distinguish observed bugs, code-supported risks and design hypotheses. Order correctness and blocked tasks before polish, and preserve established identity unless redesign is requested.

Route tasks to the relevant yp skills rather than loading all skills for every edit. Present a compact plan and proceed with authorized reversible fixes in coherent batches. A skill is guidance, not extra authority or a requirement to change every category.

Request a decision for changed scoring, data sources, schemas, core product behavior, dependencies or full redesign. Continue independent authorized work meanwhile. Preserve public API and push contracts and stored preferences.

Maintain a short internal progress note outside the published site directory. Verify each meaningful batch, stop optional retesting once concrete risks are resolved, and record a continuation point if interrupted. Finish with changed behavior, evidence, unresolved findings and clear limitations; do not stop after a report when implementation is authorized and feasible.
