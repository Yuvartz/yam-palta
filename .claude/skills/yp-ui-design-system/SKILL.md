# UI design system

Use the current HTML/CSS stack and approved assets in this repository. No framework migration, font downloads, packages or permission changes as incidental polish.

Inspect rendered screenshots and existing CSS tokens first. Retain the current visual identity unless the user requests a redesign. Consolidate compatible roles into a small token vocabulary for surfaces, text, emphasis, status, spacing, typography, radii and motion; avoid renaming the whole stylesheet without a demonstrated benefit.

Make the selected location and principal sea state visually dominant. Related metrics should share aligned labels, consistent units and number treatment. More important information deserves stronger hierarchy, not simply more cards, borders and shadows.

Define normal, pressed, focused, selected, disabled and error states for relevant controls. A selected location and a hovered location must remain distinguishable. Hover must never be the only way to discover essential data or actions.

Test long place names, three-digit values, unavailable data and larger text without clipping. Read muted text over actual surfaces at small mobile sizes. Maintain sufficient text and focus contrast; status also needs wording or shape.

Check narrow phones and desktop without blindly stretching the mobile column. Compare before/after screenshots at matching data and viewport conditions. If rendering is unavailable, describe proposed visual changes as unverified rather than finished design.
