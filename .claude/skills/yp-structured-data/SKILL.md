# Structured data

Limit changes to this repository and actual public content. Do not install SEO plugins, invent business information, submit private drafts to remote validators or publish.

Inspect existing JSON-LD and visible page content first. Choose a type only when it describes a real entity on this page; verify its current properties and any Google feature requirements against primary documentation. Schema validity and Google rich-result eligibility are different checks.

A WebSite, WebPage or WebApplication may be a candidate depending on the actual page. Do not force a type to obtain a badge or create a LocalBusiness for an informational sea app. Keep identity, URL and language coherent with canonical metadata and visible branding.

Never fabricate aggregate ratings, reviews, offers, prices, publisher identities, awards, freshness dates or author credentials. Do not mark private or invisible facts as public page content. Do not describe current sea measurements in persistent markup unless that markup updates truthfully with the displayed information.

If useful FAQs exist, evaluate markup separately from the decision to write them. Do not promise a FAQ rich result or add markup purely because a schema type is available. Omit unsupported or inapplicable properties rather than filling them with guesses.

Validate JSON syntax, references, absolute URLs and consistency with visible content. Review escaping and injection risks if any value is dynamic. Check current official eligibility requirements before reporting readiness for a search feature. Report precisely whether validation was local, schema-based, Google-specific or still pending; successful validation never guarantees a rich result.
