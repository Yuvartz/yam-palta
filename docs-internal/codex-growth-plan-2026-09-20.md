## 4. השפה האנגלית (i18n)

- **גישה:** טבלת מחרוזות `he/en` עם מפתחות, בלי שכפול לוגיקה; מתג „עברית / English”, החלפת `lang` ו־`dir`, מאפייני CSS לוגיים ו־`Intl` לתאריכים ומספרים. שעות לפי אזור הזמן של החוף; לבדוק בנפרד כיוון גרפים, יחידות וטקסט מעורב.
- **כתובות:** לבחור `/en/`, שנוצר מאותו מקור בעת הבנייה; עברית ב־`/`. ‏`?lang=en` קל לניסוי, אך ב־GitHub Pages לבדו אינו מספק HTML אנגלי נפרד. לכל שפה canonical לעצמה, `hreflang` הדדי `he/en` ו־`x-default` לעברית; גם title ותיאור מתורגמים ב־HTML. [הנחיות Google](https://developers.google.com/search/docs/crawling-indexing/managing-multi-regional-sites)
- **מינוח:** המותג נשאר YAM PALATA; „ים פלטה” בדרגה → “Flat”, „כמעט פלטה” → “Almost flat”. הסבר ראשון: “Sea flatness index”; להבהיר שהציון אינו אישור בטיחות.
- **הצדקה ומאמץ:** תיירי תל אביב ראשונים, משתמשי חופי יוון אחריהם, צוללי סיני בהמשך. אחרי בסיס ה־SEO: חילוץ ותרגום 8–12 שעות; RTL/LTR, תאריכים ושיתוף 6–10; עמודים, מטא ובדיקות מובייל 4–8. תרגום Push דורש גם שמירת שפה למנוי: עוד 3–5 שעות.

## 5. קידום במנועי חיפוש (SEO)

- **הבסיס הקיים שנצפה:** ב־`docs/index.html` כבר קיימים title עברי, description, canonical לדומיין, Open Graph, כרטיס Twitter ותמונת 1200×630, וכן `WebApplication` חינמית בעברית. ה־README מתאר GitHub Pages ואיסוף נתונים ב־Actions. לבנות עליהם.
- **עדיפות 0, השבוע — 4–6 שעות:** לאמת נכס דומיין ב־Search Console; לבדוק URL Inspection, HTML מרונדר, סטטוס 200 והיעדר חסימת אינדוקס. לבדוק/ליצור sitemap של כתובות canonical ולהגישו; לקשרו מ־robots.txt. ההגשה אינה מבטיחה אינדוקס. [Google](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- **עדיפות 1 — 6–10 שעות:** להרחיב את המבוא ל־400–700 מילים שימושיות ב־HTML ראשוני: איך המדד מחושב, מקורות ועדכניות, מצוף לעומת תחזית, מגבלות ומדוזות. H1 מוצע: „מצב הים היום ותחזית גלים לשבוע”. FAQ אמיתי יענה על „ים שטוח”, „טמפרטורת מים בים” ו„מדוזות היום”. Google מרנדר JavaScript; HTML מוכן מספק תוכן גם לפני הרינדור. [הנחיות](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)
- **עדיפות 2 — 10–16 שעות:** להתחיל בשלושה חופים נתמכים, למשל `/tel-aviv/`. Action יפיק HTML מנתוני התחזית כל 3–6 שעות: גובה גלים, טמפרטורה, שעות מיטביות, זמן עדכון ותוכן מקומי ייחודי. להשתמש באותה נוסחת מדד; בכשל להציג מועד עדכון ישן במפורש. לבחור HTML שנבנה מראש, ללא שרת חדש. לכל עמוד title, canonical וקישורים פנימיים; למקד „גובה גלים תל אביב” ו„תחזית גלים + חוף”, בלי עשרות עמודים דלים.
